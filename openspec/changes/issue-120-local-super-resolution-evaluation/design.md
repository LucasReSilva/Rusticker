## Evaluation design

### Candidate path

The primary candidate is Qualcomm's pre-exported Real-ESRGAN-x4plus ONNX model, pinned at public revision `f75f074d9e6b1adfb6da9e2afce7308a986ec88d`. The model card states BSD-3-Clause, input resolution 128 x 128, 16.7M parameters, 63.9 MB float weights, and 16.7 MB w8a8 weights; the linked float ONNX export lists ONNX Runtime 1.27.1 as its validated runtime. The source architecture and weights originate in the Real-ESRGAN project. The pinned file's LFS metadata reports 67,123,162 bytes and SHA-256 `4e1ae0e47f80d9f4aa2a317c24fde2cb3e49a5381eed6e1d509b4001a4b97ad2`; the independently downloaded bytes matched both values. At 63.98 MiB, this float artifact has a substantial first-download and cache footprint; size is recorded as a deployment tradeoff rather than a pass/fail limit. The model card's 16.7 MB w8a8 entry is not present as an ONNX file at this pinned revision and has not been tested. Qualcomm's published timing and memory figures are for Qualcomm accelerators and do not predict browser CPU/WASM performance.

A later Qualcomm repository revision, `d006168348af28d9cb65234138d6886667bd794a` (v0.34.0), publishes `Real-ESRGAN-x4plus_w8a8.onnx.zip` at 27,825,664 bytes (SHA-256 `554abcf0f7bf82ed7c4ce2a5a34de8647b76c67eb5acdaea998facb0eef787e`), or 26.54 MiB. The model card's 16.7 MB figure describes model size, not the larger downloadable archive, so the archive has a greater first-download and cache footprint than that headline suggests. Qualcomm's repository labels the revision's license `other`, and its `LICENSE` points to a separate 110 kB `DEPLOYMENT_MODEL_LICENSE.pdf` for deployable artifacts, in addition to the original model license. The quantized archive and its export recipe were not executed or independently reproduced; its artifact-specific terms still require review.

An additional candidate is Real-ESRGAN x4plus anime 6B, which the upstream project identifies for anime illustrations. SkillSafe's third-party FP32 ONNX conversion at revision `c001be50fae1c7a2bae8b2b4dec5e6fcbdbcca96` is 17,939,975 bytes (17.11 MiB), SHA-256 `9a029dae374b2cd4c3eb2dbbed857e22e6d785687c767aa12828e7356b9fb378`; downloaded bytes matched public LFS metadata. Its pinned manifest contains the claimed upstream weights hash and recipe content, but the converter source linked by the model card returned GitHub HTTP 404. The exact export has not been independently reproduced.

A separately published anime 6B export is available from BrowserSnip Upscale at commit `8e7094416ad91ec7477e968d348cd78742e20dc6`. Its `scripts/export_onnx.py` documents an RRDBNet six-block export from the upstream v0.2.2.4 PyTorch checkpoint and a PyTorch/ONNX Runtime parity check. The repository code is MIT-licensed and identifies its models as Real-ESRGAN BSD-3-Clause; these notices cover separate materials. Its exact `public/models/realesrgan-x4plus-anime.onnx` bytes are 18,371,783 bytes, SHA-256 `153c74993748fba7ce112ab749d329effb15892a14c1992b76082c92bc4d11ef`. The graph is not byte-identical to SkillSafe's export. The published exporter is a reproducible source lead, but this evaluation has not rebuilt its graph from the upstream checkpoint.

The first execution target is the exact graph in Rust/WASM. Inspect and record every ONNX operator/domain/opset in the pinned graph, then attempt loading and inference with the pinned `tract` version. A failed load or unsupported operator must include the minimal reproducer and error. Only a measured blocker permits evaluating ONNX Runtime Web's WASM backend as a fallback; do not substitute a different graph and call it the same experiment.

### Fixtures and baseline

Generate deterministic, non-private fixtures with known high-resolution references: flat-color illustration and curves, small text/glyph strokes, thin line art, a transparent foreground with antialiased alpha edges, and a photographic texture. Degrade each fixture using a documented downsample kernel and scale. Compare a conventional high-quality resize at the same target dimensions with every candidate. Record paired crops and objective measures (PSNR/SSIM where a reference exists) plus a blinded visual review for invented detail, ringing, line breaks, text legibility, alpha fringes, and crop/tile seams.

Preserve alpha by processing color and alpha explicitly; record whether the model accepts alpha (it commonly accepts RGB only), the alpha reconstruction method, and edge contamination. Exercise both whole-image and overlapped tiled inference at the same scale. Measure output dimensions and peak memory as well as visual quality.

### Gates

Do not recommend integration unless all gates pass:

| Gate | Pass condition |
| --- | --- |
| Artifact and license | Exact graph, source weights, conversion recipe, hashes, operator list, and redistribution terms are pinned and independently reproducible. |
| Rust/WASM compatibility | The exact graph loads and produces finite, correctly shaped output in the pinned Rust/WASM runtime. |
| Quality | No critical regression on any fixture; blinded reviewers prefer the model on at least 4/5 fixture classes; quantitative metrics do not regress by more than 0.5 dB PSNR or 0.01 SSIM against resize. |
| Alpha and seams | Transparent-edge color bleed is not visible at 100% review, and tiled output has no visible seams on all fixtures. |
| Runtime payload | Incremental WASM/runtime payload is at most 5 MiB compressed. Record model and archive sizes as download, startup, cache, and memory tradeoffs; model size has no pass/fail cutoff. |
| Latency | On a documented desktop, cold initialization plus one 512×512 input is at most 2 s and warm inference at most 1 s; on a documented low-resource device, cold is at most 8 s and warm at most 4 s. |
| Memory | Peak additional memory is at most 256 MiB desktop and 128 MiB low-resource, including tile buffers and runtime. |

If and only if the Rust/WASM graph fails compatibility, measure the same exact graph through ONNX Runtime Web's WASM backend. Its runtime bytes count against the 5 MiB budget. A WebGPU result is not evidence for the required CPU/WASM fallback.

### Current decision

**No-go for production integration; runtime compatibility probe passed, product gates did not.** `tract` 0.23.8 parsed, optimized, and ran Qualcomm's pinned FP32 graph natively and in a `wasm32-unknown-unknown` build invoked under Node's WebAssembly runtime. The 67,123,162-byte model has a 63.98 MiB first-download and cache footprint. The graph is opset 17 with one `[1,3,128,128]` input, 1,094 standard-domain nodes, and no custom domains: Conv (351), LeakyRelu (279), Concat (276), Add (93), Mul (92), Resize (2), and Clip (1). Both runs returned a `[1,3,512,512]` F32 output for a zero tensor. Native inference took 11,334 ms after load/optimization; the WASM call took 87,621 ms including graph load and optimization. The measured generated WASM was 86,571,967 bytes raw, 65,740,805 bytes gzip level 9, and 64,663,045 bytes Brotli quality 5, with the model embedded. That packaged evaluator is large and the single graph call is slow, which weighs against startup and low-resource use. These are compatibility probes, not image-quality results or comparable cold/warm performance measurements. Node is a WASM host, not the app's browser worker. The temporary artifact was downloaded with a TLS-validating Node HTTPS client after the Git-for-Windows curl client failed with Schannel `SEC_E_NO_CREDENTIALS`; the hash matched the model repository's LFS metadata. Synthetic fixture comparisons, alpha/seam checks, browser worker execution, warm/cold browser timing, and low-resource device memory/latency remain unmeasured for this graph.

The published W8A8 archive is 26.54 MiB before extraction, compared with the model card's 16.7 MB figure. Its deployable-model license is supplied separately from the BSD-3-Clause source-model license, so redistribution is not cleared by the repository's top-level BSD label alone. No exact quantized graph was run. The existing Node probe establishes that the Qualcomm float graph can execute as WASM, but its 87.6-second single call and 64.7 MiB Brotli binary with the model embedded point to substantial startup, download, and cache costs. Browser and low-resource performance remain unknown.

The anime 6B ONNX file is 17,939,975 bytes (17.11 MiB), giving it a first-download and cache footprint of that size before compression; there is no model-size cutoff. Its source weights and architecture have an upstream BSD-3-Clause notice; the model card declares the same license, while its linked converter repository and its license were inaccessible (GitHub HTTP 404). The manifest embeds a recipe description, but the conversion implementation and byte reproducibility have not been verified. Native `tract` 0.23.8 processed a deterministic 64x64 flat-region/diagonal-line fixture into finite 256x256 F32 output in 810 ms after load/optimization. A `wasm32-unknown-unknown` build ran the exact graph under Bun's WebAssembly runtime with exit code zero in 8,954 ms including load, optimization, and inference. The model-embedded WASM measured 37,415,621 bytes raw and 19,233,441 bytes Brotli quality 5. The model alone measured 16,596,135 bytes Brotli quality 5, making the 2,637,306-byte compressed difference an indicative packaged-runtime increment rather than a separately measured runtime artifact. The output range was -0.0111 to 1.1055 before clipping. The three-channel graph has no alpha input; alpha reconstruction and seam handling remain untested. A single nonzero fixture is only an execution smoke test, not a quality comparison against resizing.

**No-go remains:** no screened candidate has passed all artifact, provenance/license, quality, browser-worker, latency, and memory gates. The SkillSafe anime 6B conversion's unavailable converter source prevents independent reproduction and complete conversion-notice review. Its exact graph passed a standalone browser module-worker probe in HeadlessChrome 155 on Windows x64 with GPU disabled: the 37,415,641-byte model-embedded WASM compiled in 168 ms, and model loading, optimization, and one generated 64x64-to-256x256 fixture call took 6,936.6 ms (7,104.6 ms total). This is a single cold call, not warm timing, a 512x512 measurement, or execution in the app's integrated detector worker; it shows browser WASM compatibility only. The browser worker returned a success code after finite-output checks; the native run on the same graph reported `[1,3,256,256]`. The separately published BrowserSnip export fails the current `tract` 0.23.8 native probe during shape analysis: node `#195 "node_conv2d" ConvHir` cannot unify symbolic `H,W` with values `64,64` for a `[1,3,64,64]` input. The exact graph passed in a HeadlessChrome 155 module worker with ONNX Runtime Web 1.30.0's CPU WASM provider, returning finite `[1,3,256,256]` output. Across three runs, session load and initialization took 379.8–650.7 ms; first inference took 1,705.6–1,895.9 ms and the second 1,697.0–1,900.6 ms. Its 14,290,023-byte raw WASM-plus-loader payload compresses to 2,840,633 bytes with Brotli quality 5, within the 5 MiB runtime payload gate. These are 64x64 smoke timings on a desktop browser with a loopback-served model, not the 512x512 latency or memory measurements. Both anime 6B graphs have three-channel inputs and need separate alpha handling and tile-seam review. Synthetic fixture comparisons and low-resource device latency and memory are still unmeasured. Do not add a production dependency.

### Reproduction record

The checked-in evaluation harness records acquisition, hash verification, native runs, wasm32 builds, and WASM invocation under Node for the Qualcomm float graph and Bun for anime 6B. See `tools/issue-120-onnx-evaluation/README.md` for commands. On the earlier Qualcomm run, Cargo needed a temporary uncommitted resolver stub for the disabled optional `tract-transformers` dependency because crates.io was unreachable and the local index lacked its metadata; that stub was removed and was not used to execute the graph. The fixed-shape Qualcomm graph still uses a zero tensor; the dynamic anime 6B graph uses generated flat regions and a diagonal line. Full quality and device measurements require more fixtures and a browser harness.

Model acquisition and `tract` execution commands have been validated in the checked-in evaluation harness. Operator inventory was completed for Qualcomm's float graph; the anime 6B graph's full operator inventory remains pending. Multi-class fixture generation, interpolation comparison, alpha/seam review, browser-worker invocation, warm inference, and target-device memory sampling remain future harness tasks.
